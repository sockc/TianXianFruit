# 天鲜账本 V1.4.7.15

本版集中收口资金结算体系，不再增加新的结算概念。

## 1. 历史旧版 B↔C“结清截至今日”迁移

V1.4.7.14 已经把新的最少转账方案和“结清截至今日”统一为“资金中心 ↔ 合伙人”，但旧版本曾经生成过不经过资金中心的 CUTOFF 记录，例如 B → C、C → B。这些旧记录即使重新生成当天资金轧差也不会被删除，因此仍会继续影响资金余额。

V1.4.7.15 升级 DB_VERSION 22，并在数据库升级时做一次迁移：

- 旧 CUTOFF 如果一端是当前资金中心：转换为 `CUTOFF_CENTER`，继续作为有效真实结算。
- 旧 CUTOFF 如果双方都不是当前资金中心：转换为 `CUTOFF_LEGACY_INVALID`。
- `CUTOFF_LEGACY_INVALID` 保留在结算历史中，显示“旧版结算 · 已失效”。
- 已失效旧记录不再参与任何资金余额、期间已执行转账或结算事件计算。
- 迁移会更新 `sync_status / updated_at`，后续继续通过现有云同步同步到其他设备。

这解决了“当天没有营业，但旧 B→C 结算仍然把资金余额扣掉”的问题。

## 2. 最少转账方案仍是唯一日常结算方式

- 当日资金差仍按：`采购垫付 + 费用垫付 + 当日利润/亏损 - 当日营业收款`。
- 所有新方案只允许“资金中心 ↔ 合伙人”。
- 非资金中心之间不再生成 B → C / C → B。
- 当天存在实际已确认转账时，禁止直接重新生成，避免覆盖真实流水。

## 3. “结清截至今日”统一资金中心规则

- 对普通合伙人点击“结清截至今日”，直接取该合伙人点击前的完整累计未结余额。
- 应收：资金中心 → 合伙人。
- 应付：合伙人 → 资金中心。
- 一次结清后该合伙人的累计未结应归零（允许分币四舍五入误差）。
- 资金中心本人不提供“结清截至今日”。

## 4. 资金余额总览与合伙人卡片

总览显示当前筛选期间：

- 采购金额
- 营业额
- 利润
- 已执行资金结算
- 待结人数
- 资金中心待收
- 资金中心待付

普通合伙人卡片显示：

- 个人采购
- 个人营业收款
- 个人利润 / 亏损
- 期间已执行转账
- 当前累计未结
- 未结时间范围与营业日数量

资金中心卡片额外拆分：

- 个人经营资金差
- 当前待收合伙人
- 当前待付合伙人
- 累计代收合伙人
- 累计代付合伙人

## 5. 经营日期明细与结算事件分开

- “经营日期明细”只由真实经营/采购/利润数据日期组成。
- 单纯发生转账但没有经营的日期，不再伪装成一个营业日。
- 实际转账单独进入“结算事件”，显示日期、转账方向、金额、类型和确认时间。
- “涉及营业日”仍只统计真实营业日。

## 6. 利润 / 亏损分担状态简化

“当日结算”里的利润区域只负责确认当天分配结果：

- 显示合伙人
- 显示当天保存的分配百分比快照
- 显示当天实际利润 / 亏损金额

删除旧的“累计已结算利润 / 待结算利润 / 确认利润已结算”操作。资金是否实际结清，只由最少转账方案、资金余额和结算记录判断。

## 7. 结算记录与撤销

- 继续统一展示最少转账方案和“结清截至今日”的真实转账。
- 保留结算时间范围、营业日数量、确认时间和转账方向。
- 有效“结清截至今日”可撤销；撤销后原经营数据不变，金额重新进入资金余额。
- 旧版非资金中心 CUTOFF 显示“旧版结算 · 已失效”，只保留历史，不提供撤销入口。
