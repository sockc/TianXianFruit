# 天鲜账本 V1.4.7.46

## 本版重点

### 天气缓存重构
- 首页、营业页、天气详情共用本地 `weather_cache`，不再因为页面来回切换反复请求天气接口。
- 今日天气缓存 10 分钟；未来日期缓存 30 分钟。
- 缓存过期时先显示旧数据，再后台静默刷新（Stale-While-Revalidate），避免天气卡反复空白/转圈。
- 首页与营业天气显示“更新于 HH:mm”；后台刷新时显示“后台更新中”。
- `weather_cache` 仅保存在本机，不参与云同步，不污染经营历史。

### 营业天气快照完整同步
- `weather_snapshot` 正式加入 Android 上传权限，使用 `business.edit` 权限。
- 天气快照新增 `store_sync_id`，跨设备按经营位置的稳定 `sync_id` 映射，不再依赖每台手机不同的 SQLite `store_id`。
- V25 已产生但尚未上传的天气快照升级时自动改为稳定同步 ID，并重新进入待同步队列。
- 云端下载天气快照时自动映射到本机经营位置，避免串位置。
- 营业页同步状态同时感知 `store_daily_record` 与 `weather_snapshot`。
- 经营分析同步状态加入营业、采购、库存和天气快照。
- 完整 JSON 备份加入 `weather_snapshot`；天气缓存不进入备份。

### 天气快照与缓存分离
- 首页/天气详情只读写临时天气缓存，不再把普通查看行为写成经营历史。
- 营业页第一次读取天气时保存营业前 `FORECAST` 快照；当天实际天气 `ACTUAL` 在获得新天气数据时更新。
- 经营分析继续读取同步后的营业天气快照，为后续“营业预测”准备稳定历史数据。
