# 正式账本营业写入准入审查（iOS V0.4.9 / Server V1.0.29）

状态：**未放行正式账本修改**。本文件记录实际源码限制，不代表上线许可。Android 现有“当日结算”规则及其自动作废派生数据的能力不应由 iOS 覆写。

## 已具备

- iOS 创建一笔 `iOS_TEST_` 营业记录，用户已在安卓设备完成真实双端同步验证。
- 服务端 `/api/v1/business/commit` 按操作 ID 和 canonical hash 幂等创建；与 `/sync/push` 的 `store_daily_record` 共享 Book 行锁；只允许测试账本并且默认关闭。
- iOS 现有 `TestBusinessEditPolicy` 对旧记录的身份、原多收款人明细、原利润校验；发现当日利润分配、结算或转账证据后拒绝编辑。
- 测试账号编辑以原 `sync_id`、单步 `row_version+1` 写入，随后拉取服务器做逐字段回读；结果未知时不自动重发。
- 安卓 64 位整数 `id` 通过服务端精确处理，不能通过 JavaScript Double 逆推数字身份。

## 正式更正仍不能放行的阻塞项

1. V1.0.29 没有专用的**营业更正原子接口及服务器级别的更正幂等操作记录**。现有 `/api/v1/sync/push` 是 Android 通用同步，不能直接作为 iOS 正式账本更正 API。
2. Android 对营业更正可能需要撤销或更新已生成的利润分配、资金结算、转账衍生数据；服务器 `/sync/push` 尚未在同一事务中执行与 Android 一致的衍生数据处理。iOS 客户端的“已有结算就禁改”只是额外保险，**不能取代服务端锁内校验**。
3. 正式写入前必须核对 Android 的凌晨收款归属、自然日及多位置同收款人情形；不得把凌晨收款自动塞入营业事务，也不得修改其现有口径。
4. 必须核对重试、断线、权限变化、并发两端修改时的服务器行为，包括 64 位数字 ID 的精确保存和收款人拆分。
5. 必须提供明确的运营开关及账本白名单/灰度控制，不能通过全局 `TIANXIAN_BUSINESS_COMMIT_ENABLED=true` 绕过测试账本保护。

## 本版准入范围

- 正式账本：查看云端营业明细、金额、每位收款人归属；**只读**。
- `iOS_TEST_` 测试账本：从营业历史点进详情，再进入既有安全更正流程；只允许修改金额/支出/库存估值，禁止更改日期、位置、收款人身份或凌晨规则。
- 已结算日期、旧版非稳定营业 ID、无收款人明细、离线缓存授权、VIEWER 权限：关闭更正入口。
- 本版**不升级服务器，不新增数据库迁移，不要求重新创建测试账号**。

## 最少验收

1. 既有测试账本选一笔**未结算**营业记录，改动一项小金额；云端核对后安卓只同步一次，确认金额及收款人一致。
2. 已结算营业日和正式账本的详情仅能查看，不能进入更正。
3. 任何异常不盲目重复提交，保持原记录和安卓结算安全。
