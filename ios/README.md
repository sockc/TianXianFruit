# 天鲜账本 iOS V0.5.1 / Build 33 — 采购优先

## 本版更新（仅列当前版本）
- **采购主链路**：在「采购」选择日期、采购人和商品，填写数量、单价与金额，先本机保存；在 `iOS_TEST_` 测试账本且服务器 V1.0.30 允许采购原子提交时，点击「上传采购到测试账本」，一次事务生成 `purchase_order`、`purchase_item`、`purchase_activity`，随后从云端逐单逐商品回读，安卓同步后可见。
- **17 位安卓数字 ID**：采购人、商品、采购计划、采购协作、订单及商品明细的跨表关联统一使用精确 `Int64`，不经 `Double` 四舍五入；同表重复编号阻止操作。
- **安全性**：采购上传只在测试账本可用；正式账本采购仍可本机草稿录入，但云端写入不开放。服务器 V1.0.30 即使全局写入开关为真也会拒绝正式账本提交（HTTP 403）。已结算日禁止添加采购，已有同日采购疑似重复需核对，不自动生成第二单。
- **断网保护**：提交操作先写本机不可变事务记录；超时或不确定时只读查询原操作，不自动生成新编号或盲目重发。
- **入口**：测试账本采购页可刷新服务器能力检查，不用重新登录或新建测试账号。
- **范围**：仍沿用 Android 已保存的当日结算/凌晨收款/采购成本口径，不修改其计算；测试账本采购计划联动使用现有 CAS 版本机制，但实际安卓双端核对以用户操作结果为准。

## 部署和使用
服务器从 **V1.0.29 → V1.0.30**，上传同名 PATCH.zip 后使用内附 `scripts/install-purchase-testbook-v30.sh` 安装；升级本身不启用写入。测试账本专用写入启用后，用 TrollStore 直接覆盖安装 **Build 33**（iPhone X / iOS 16.6），不要卸载旧版，以保留本机草稿。使用原 `iOS_TEST_` 账号验证一次正常采购 → 安卓同步，无需逐项手动回归测试。

本版新增接口是服务端已有原子采购能力的安全限定和客户端 Int64 兼容，不代表生产正式账本采购可写。
