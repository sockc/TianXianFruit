# 天鲜账本 iOS V0.6.5 · Build 42 — 安卓资金余额与周期结清历史（第二阶段）

## 本版本完成
- **结算表新增「资金余额与结清历史」**：既可从结算表进入，也可以从「更多」直接进入。采用「逐日资金 / 周期结清记录」两种视图；默认最近7天，可切换近30天或全部，并支持左右切日、日历、合伙人筛选和懒加载。
- **合伙人逐日资金**：显示同步过来的 settlement_partner 原始日资金差额，按日、合伙人分组；可展开查看采购垫付、费用垫付、收入、利润份额及应留存款，及当日已保存转账方案和登记金额。**逐日资金差额不是当前跨日累计余额，不会相加冒充当前应收应付。**
- **资金历史登记**：支持 CUTOFF / CUTOFF_CENTER / LEGACY / CUTOFF_LEGACY_INVALID；按照实际已保存的 batch_key（及记录日期、类型）成批展示，缺失 batch_key 的记录绝不合并。显示覆盖营业期间、结清对象、方案总额、登记总额和逐笔明细，不把覆盖日期误归为登记日期。
- **撤销与无效记录区别**：已确认过但 settled_amount 被清零的周期结清标注“已撤销（原登记清零）”；安卓指定的 CUTOFF_LEGACY_INVALID 标注无效，不计入当前资金余额。对超额/负数登记发出异常提示。
- **跨端安全**：沿用全部同步版本与墓碑删除机制；没有增加资金写入请求，也没有修改安卓当日结算、资金中心和跨日清零规则。
- **专项测试**：每日原始资金、跨日期筛选、多记录同批汇总、无 batch_key 分离、撤销/无效历史、墓碑删除、周期记录日与覆盖营业日期区别。

## 当前累计余额的边界
安卓资金余额 getPartnerFundBalances、每日历史 getPartnerDailyFundBalances 会计算全历史转账、资金中心镜像、周期清零和部分结算。目前 GitHub 中可访问的项目仓库只有 Android/iOS，未提供可修改的正式服务端计算接口；已同步原始记录也没有权威的**当前累计余额**字段。为避免错账，本版顶部明确显示「当前累计余额：待权威接口」，不展示猜测余额。后续服务器提供只读权威余额 API 后，iOS 再调用并回读验证，而不移植另一套不一致的算法。

## 安装
GitHub Actions 生成 TianXianFruit-iOS-v0.6.5-Build42-TrollStore.ipa。iPhone X / iOS 16.6 用 TrollStore 覆盖安装；勿先卸载，避免丢失本机草稿及提交锁。无需更新正式服务器；本版不开放正式账本资金写入。
