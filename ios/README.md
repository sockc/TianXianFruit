# 天鲜账本 iOS V0.4.9 · Build 31 — 修复营业更正误判

本版修复“安卓或其他设备已修改此记录，原数据未覆盖”误报及客户端本机缓存混入更正基线的问题。

- **更正列表只使用新鲜、完整的服务器 GET /sync/pull 结果**：自动复用已有专用测试登录，不再将旧版本机只读 SQLite 缓存作为原营业记录。旧版可能把 17 位安卓 Int64 编号缓存为精度不足的 Double；同一云端版本因此可能在原逻辑的全 JSON 相等检查中被错误判为发生修改。
- 已进入更正表单后，如另一设备真的修改记录，仍核对源记录 sync_id、row_version 和完整云端内容并停止发送；提示“更正未发送”、源版本及最新云端版本。
- 第二次提交前检查若冲突且尚未向服务器发送写入请求，撤销仅本机的未发送预约，不再永久锁住这笔营业；**真正已发送或结果未知的任务仍不能重发**。
- 已存在的测试账号凭据自动验证并拉取最新记录；点击右上刷新只更新该受控测试会话的数据。
- 只允许 iOS_TEST_ 测试账本更正未结算营业记录，不改凌晨收款、收款人身份、位置、日期或安卓结算规则。正式账本仍只读。
- 本次只更新 iOS，服务端沿用 V1.0.29，不迁移数据库、不重建账号。

安装：用 TrollStore 覆盖安装 Build 31，不卸载原应用。选择“营业”→已有记录→“更正此笔营业”，应用会自动拉取云端新数据。已发送结果未知的旧任务必须先通过“只读核对云端”确定状态。

# 天鲜账本 iOS V0.4.9 · Build 30

**本版目标：正式营业可查看详情、测试账本可从历史记录直接进入现有营业更正。** 不修改安卓当日结算和凌晨收款逻辑，不需要服务端升级或重复创建测试账本。

## 当前版本变更

- 在「营业」页直接点历史日期下的某个营业位置，查看云端已保存金额（微信／支付宝／现金／支出／库存估值／利润）与逐收款人归属。
- `iOS_TEST_` 测试账本有编辑权限、云端稳定 Android 营业 ID、完整收款人拆分、未结算且处于在线授权时，可进入既有“测试营业更正”流程。
- 更正保持原营业日期、位置、收款人身份；服务端版本变化则不覆盖；失败不自动重试。以前保存的专用测试登录凭据自动复用，缺失时才要求首次验证。
- **重要：云端 JSON 中大于 `2^53-1` 的安卓 64 位数字 ID 改为 Int64 无损保存和回传，防止修改时把 17 位原始 ID 重新编码为相邻编号。**
- 正式账本依然只读。生产更正的服务端原子事务、派生结算一致性、跨端冲突保护尚未达到放行标准，见 `PRODUCTION_BUSINESS_READINESS.md`。

## 使用

使用 TrollStore 在 iPhone X（iOS 16.6）覆盖安装 Build 30，**不要先卸载原 App**。原测试账号打开「营业」→ 点击已同步位置 →「更正此笔营业」；已有测试登录状态可复用，不需重新录入营业。正式账本只查看详情。

自动 CI 通过不等于安卓端实际同步验证；升级仅需核对一笔测试账本中没有结算的更正记录，并在安卓端确认金额与收款归属。

# 天鲜账本 iOS V0.4.8 Build 29 — 营业原操作安全续传

本次为 V0.4.8 的定向修复版，不新增服务端版本，不修改安卓结算算法。解决已保存营业草稿出现“结果不确定，禁止再次上传”且 GET 原操作返回 404 后无法继续的问题。

- 原因：旧版在 POST 之前先写入 unknown，若权限检查/服务器开关在 POST 前拒绝，草稿也会被锁定。
- 修复：用户查询原操作返回 404 后，可以主动点击「继续原操作」。仅允许 iOS_TEST_ 测试账本，**复用 SQLite 中的原操作 ID、原请求内容、原哈希**，先完整同步云端并排除同日同位置记录，由已开启的 V1.0.27 原子营业接口处理幂等。
- 云端已有原操作则只回读确认，不重复 POST；有同日期同位置营业冲突则停止；断网或权限关闭时保留锁定及草稿，不自动重试。
- V1.0.27 已支持账本行锁、按原操作 ID 与 payload_hash 去重；客户端不能用新编号绕过该锁。
- 同步保护：未启用营业写入时「继续原操作」不可用；新增「刷新服务器写入权限」以避免每次重新打开页面。
- 修正提示文案：未知结果不再错误显示“未提交云端”。

**安装**：iPhone X（iOS 16.6）使用 TrollStore 覆盖安装 Build 29，不卸载旧版；需要在原测试账本登录并由服务器开启营业原子写入。源代码及 IPA 须以 GitHub Actions 最终构建结果为准。没有经过真实双端账目核对前不能视为正式版本。

# 天鲜账本 iOS V0.4.8 — 正式营业隔离保护

**版本 0.4.8 / Build 28**。与 TianXian-Server V1.0.27 的限制一致：只有名称严格以 `iOS_TEST_` 开头的测试账本才可能启用正式营业事务提交。其他账本依然可查看和保存本机营业草稿，但「提交正式营业」始终禁用。

服务端还要求在线编辑权限、设备验证及 `TIANXIAN_BUSINESS_COMMIT_ENABLED=true`，默认关闭。客户端开关或缓存不构成授权。未取得服务器能力时，保持禁用。旧安卓结算规则不变。V1.0.27 服务端还将 PostgreSQL 建表和兼容迁移放入同一 advisory transaction lock 防并发重复创建数据库对象。

当前源码已提交 GitHub；iOS IPA 编译与安卓/iOS 双端联调未验证，不宣称已可发布。

# 天鲜账本 iOS V0.4.7 — 安卓营业结构对齐

**版本 0.4.7 / Build 27**，支持 iPhone X / iOS 16.6 / TrollStore（最低 iOS 15），Bundle ID 不变。覆盖安装保留本机草稿；请勿卸载旧版。

## 本版修改

- 找回资料库中 **TianXian-Server V1.0.25-PurchaseAtomic FULL** 真实源码，并在其基础上编写 **Server V1.0.26-BusinessAtomic FULL/PATCH**（当前只是交付源码，没有部署线上）。
- Android 正式营业逐人收款实际存储在 `store_daily_record.receipt_splits_json`；修复 V0.4.6 中误认为独立 `store_daily_collector` 的回读逻辑。
- iOS 录入表增加必填「支出 / 开摊库存估值 / 收摊库存估值」，对旧本机草稿缺少这些值的情况保持空白，禁止默认为零。
- 服务端采用 Android 现有利润计算式：`profit = revenue + stock_left_value - opening_stock_value - expense`。客户端将四项作为不可变事务载荷的一部分，服务端自行复算。
- 保留营业草稿账号/账本隔离、服务器事务能力检测、双次完整刷新、同日同位置防重复、SQLite 操作锁、异常只读查询和回读校验。
- 新服务端营业接口默认关闭：`TIANXIAN_BUSINESS_COMMIT_ENABLED=false`，即使客户端版本升级，也不会自动开放正式账本写入。

## 服务器匹配条件

正式服务器升级、PostgreSQL 并发核验、安卓客户端真实字段回读、账号权限与独立测试账本确认之前，不得手动打开营业写入开关。当前未部署 V1.0.26，iOS 上传按钮依然禁用。

V0.4.7 **不修改安卓当日结算、利润分配、资金转账及凌晨收款算法**。一切正式营业提交须使用专用原子事务，不通过 `/sync/push` 伪造多记录事务。

详见 [BUSINESS_COMMIT_CONTRACT.md](BUSINESS_COMMIT_CONTRACT.md)。
