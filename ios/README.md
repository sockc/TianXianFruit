# 天鲜账本 iOS V0.5.2 · Build 34 — 采购计划完成联动

## 当前版本更新
- **待采购直接录入**：进入「采购」选日期，在「待采购」按采购人分组的商品下点击「填写实际采购」，自动带入原计划商品、单位、建议数量、每件重量和计划源 ID；单价仍为 0，须由用户确认实际单价，不使用计划估算价冒充成本。
- **多采购人**：已分配采购人时自动选定；未分配而有多名可选采购人时弹出选择；同一计划已存在本机草稿则直接继续编辑，禁止为同一来源再建第二份草稿。
- **防错关联**：计划采购的日期、采购人、商品和单位不可在编辑时随意改变；仅允许修改实际采购数量、单价、重量、备注。缺少协作记录、商品身份不一致、计划已完成或 Android 17 位 ID 无法精确对应时不带入。
- **原子完成计划**：先保存本机草稿，随后在「本机采购录入」点击上传。服务器 V1.0.30 在同一事务内新增 `purchase_order`、`purchase_item`、`purchase_activity`，并更新 `purchase_plan_item` 与 `purchase_collaboration`。账本没有 `purchase_plan.edit` 权限时清晰提示，不会误以为已完成。
- **云端逐项回读**：采购回读不仅核对正式订单和每个商品金额，还检查关联待采购项目的完成状态、采购人身份、实际数量、实际金额及订单关联，未完整回读时显示待核对而不宣称成功。
- **多单与重复保护**：同一采购人已有其他订单时允许提交不同且仍待完成的计划；原操作 ID 不变，异常不自动重复 POST，另由服务端 CAS、相同金额防重及结算日保护最终判定。
- **安卓现有成本与库存**：不新增或伪造库存快照。已完成采购由安卓原有采购/库存读取链路处理；本版不修改安卓当日结算、凌晨收款、利润和资金轧差算法。

## 安装和前提
TrollStore **覆盖安装** Build 34（iPhone X / iOS 16.6），**不要卸载旧版**，以保留本机采购草稿和幂等操作记录。服务端继续使用已验证的 **V1.0.30**，测试账本采购写入已启用；**本版无需服务器升级**。正式账本仍只读/本机草稿，不开放采购正式写入。

在原 `iOS_TEST_` 测试账本里，只需使用一条安卓真实待采购计划，填真实数量和单价，确认上传一次，再在安卓同步查看待采购是否成为已完成。不要求重复新建账号或逐项人工回归。
