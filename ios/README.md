# 天鲜账本 iOS V0.3.4 — 新增营业支持逐人收款和实际营业时间

**版本 0.3.4 / Build 19**。适用于 iPhone X、iOS 16.6 和 TrollStore（最低 iOS 15），无须 Apple 开发者证书。Bundle ID 保持不变。**仅用 TrollStore 覆盖安装，勿卸载旧版**；原本机草稿、测试提交任务及专用 Keychain 会话可继续保留。

## 当前版本新增

- 在「更多 → 写入测试实验室 → 营业草稿」增加**“按收款人逐人录入”**开关。同一微信/支付宝/现金渠道可以有多位收款人：每个收款人分别选已同步合伙人，填写该人三个渠道的实际金额，页面实时汇总，不再用“一渠道固定一个收款人”的旧版限制。
- 保存本机草稿时严格检查：每人身份唯一且非空、至少一个非零支付渠道、最多 12 人、金额精确到分、所有逐人金额之和与三大渠道汇总完全一致；**不允许在上传时猜测、按比例补分或者把未知收款归到别的合伙人**。不符合条件仅提示错误，不发送云端。
- 营业草稿另增可选的 **实际开摊时间与收摊时间**（24 小时制 `HH:mm`，例如 `16:00` 和 `00:10`）。开始/结束必须同时填写或同时留空，不得完全相同；结束时间早于开始时间表示跨午夜营业。它**只保存 Android 的实际时间字段，不产生凌晨收款、跨日扣减或结算写入**。
- 「测试营业同步」把按人数据转成安卓兼容 `receipt_splits_json`，先核实每个收款人稳定云端 ID、完整金额和同日同位置唯一身份，再使用原有不可变 SQLite 提交意图一次性上传。上传前新增第二轮云端同位置重复检查；服务端 ACK 后核对时间、营业额、利润及收款明细。
- 不影响旧版单渠道收款人草稿：`businessCollectors` 为可选扩展字段，V0.3.3 及之前本机草稿仍可读取并沿原路径提交。
- 保留 V0.3.3 营业逐人更正、已结算日期禁改，V0.3.2 四类同步核对中心，测试采购新增/备注更正及正式账本只读分析。新增营业逐人录入、跨午夜营业时间、错误金额和跨版本草稿兼容的 XCTest。

## 最少验证

1. iPhone 直接覆盖安装，在独立 `iOS_TEST_` 测试账本的「写入测试实验室」选择营业，开启“按收款人逐人录入”。
2. 例如选择甲：微信 60、现金 40；乙：微信 40、支付宝 20，输入实际时段 `16:00` 至 `00:10`，保存一次本机草稿。
3. 进入「测试营业同步」提交这笔**全新的同日同位置测试营业**一次，再到「测试同步核对中心」只读检查云端成功与否。Android 端仅需在同一测试账本同步后查看收款明细与时间是否一致。无须重输账本 ID 或批量反复测试。

## 写入边界

- 本次**仅改 iOS 开发分支及其自动测试/打包文件**；不修改 Android、正式服务端、利润分配、资金结算或安卓当日结算计算逻辑/UI。
- **正式账本始终只读；所有提交只能进入名称以 `iOS_TEST_` 开头、由专用普通 USER 单账本测试账号核准的独立账本**。
- 删除营业、修改日期或位置、凌晨收款的录入/扣减、已有结算日的财务改动、资金结算及正式账本的双向写入尚未开放。
- 客户端两轮对比并不等价于服务器事务级 CAS。服务端并发与结算联动未完成独立审计，因此**不得使用真实经营数据进行 iOS 写入测试**。GitHub 自动测试通过不等于双机真机验收。
