# 天鲜账本 iOS V0.2.4 · 采购小批量试运行与订单 ID 重映射

适用 **iPhone X / iOS 16.6 / TrollStore**，最低 iOS 15。Bundle ID `com.tianxian.fruit.ios` 不变，版本 0.2.4、构建号 9。**请覆盖安装，不要卸载应用或清除数据**；保留 V0.2.0–V0.2.3 的草稿、独立 SQLite 上传队列及已有云端核对状态。

## V0.2.4 新增

1. **分阶段放开最多三笔单商品测试采购**：第一笔可按原规则提交；第二、第三笔准备前，先对该设备之前的所有采购重新使用 `GET /sync/pull` 云端核对订单、商品明细、数量、金额和父子订单 ID，且必须已由用户在 Android 同账本里核对并手动登记时间。任一笔未完成、异常、无 Android 人工确认，禁止准备下一笔。三笔上限是**本机测试队列限制，不是后端硬配额**，不是允许量产。
2. **识别服务器数字 ID 重映射并安全发送子明细**：订单 `purchase_order` 上传得到 accepted 和回读后，以服务端**实际**父订单数字 `id` 作为唯一父子关联来源，先把它冻结保存到本机 SQLite，再给 `purchase_item.order_id` 使用。商品明细 `sync_id`、总价、数量、商品引用不变。如果再次回读发现父订单 ID 已改变，立刻停止发送子明细并转入待核对。
3. **不可逆出网标志**：发送商品明细之前，先把 `itemRequestStarted` 本机持久化。一旦发送过程发生超时、断网或进程中断，后续再查看云端不能将“没有读到商品明细”武断判为“可重新上传”；需要人工核对，不自动重发。
4. **防不同设备并行试写**：准备第二、第三笔之前，若测试账本云端出现本机任务不认识的 `ios-stage-order-` 记录，则停止准备，不与其他 iOS 设备并行试写。
5. **清晰的进度提示**：显示已准备 / 3 笔、商品明细绑定的服务端父订单 ID、出网结果不确定的警告。继续显示云端订单金额/商品明细核对，以及 Android 人工验收状态，绝不把云端成功误认为 Android 已同步。
6. **升级兼容**：旧版草稿没有 `childParentID`、`itemRequestStarted` 时按未知状态解析，保留原上传意图；不会隐式创建新的云端 `sync_id`，也不会自动上传。含异常历史状态的订单需先人工核对。
7. **同步删除墓碑修复**：读取最新记录时保留 DELETE 墓碑，已删除的采购订单或商品明细明确显示为已删除，不再误显示为普通缺失；已删除的采购人、商品也不能作为新采购引用。修复此前 V0.2.3 单元测试发现的问题。
8. **专项测试**：增加八组采购扩容和四组删除墓碑测试：远端数字 ID 重映射、父子 ID 冻结不可修改、子请求必须先落盘、第二第三笔审核、第四笔拒绝、缺 Android 验收拒绝、远端金额变更拒绝、跨账号/账本拒绝与旧 JSON 解码；原有测试继续保留。

## 必须继续执行的安全限制

- **仅固定现有服务器** `https://sync.830888.xyz`，使用一个仅能访问当前测试账本的专用 `USER` 账号；`GET /books` 必须恰好只有一个 `iOS_TEST_` 账本，角色 OWNER/EDITOR，名称与本机草稿的完整账本 ID 一致。不能把正式账本改名测试账本。
- iOS 正常登录 `CloudAPI` 保持业务只读。只有“更多 → 采购小批量同步”内，在核对账号/账本/草稿且用户每笔明确点击确认后，独立写入客户端才可能提交一个 `purchase_order` 和一个 `purchase_item`。
- **不会开放正式营业、凌晨收款、利润分配、资金结算、库存扣减或客户交易写入**，Android 当日结算计算/UI/字段与 APK 发布工作流完全不变，也不修改正式后端。
- 本机限制并不等于服务端已经实现跨账本强授权。生产后端每次 `/sync/push` 都必须正确验证 token、`book_id`、采购行所属账本及父子引用；此服务端源码未在本次 iOS 项目中可审查，**真实后端权限仍需确认**。
- 如果有服务器版本冲突、订单/商品金额变化、远端缺失或父子关联错误，绝不自动重试同一订单或产生新的记录。需保留草稿并人工处理。

## 验收步骤

1. 用 TrollStore **覆盖安装** V0.2.4，确认原有本机采购草稿仍存在。
2. 在独立测试账本 `iOS_TEST_` 里，用只能访问该账本的普通测试账号登录“采购小批量同步”。
3. 对已上传的第一单点击“刷新云端对账（仅查询）”，确认金额、商品、数量及父子 ID 一致。然后**亲自在 Android 同一测试账本检查**，点击人工核对确认；没有这个确认就不能开始第二单。
4. 选择第二笔草稿，点击“核验上一单并准备本笔采购”，由客户端重新读取第一笔完整云端数据，确认后再明确试写。第三单操作相同。
5. 遇到父订单数字 ID 重映射，检查“商品明细使用云端父订单 ID”显示并从 Android 验证。若服务器更改了其他数值字段或父子关系，App 会停止并显示异常。
6. 第四单在这个版本应该明确拒绝准备；如果出现错误或未确认的采购单，后面的测试应被锁定。
7. 最后核对 Android 正式账本的采购、库存、营业额、凌晨收款和当日结算没有变化。

## CI、下载及当前限制

通过 GitHub Actions “Build TrollStore IPA (no Apple certificate)” 的成功任务，在 Artifacts 下载 `TianXianFruit-iOS-v0.2.4-TrollStore`。新版本无 Apple 开发者证书要求。模拟器专项测试和静态隔离检查由 `check-ios.yml` 执行。

**云端回读正确不等于 Android 已自动收到**，人工验收只在本机记录。这个版本仍是小批量验证，不包含一单多商品、批量结算、采购跨设备冲突自动合并或服务端全局数量上限。若父订单/采购人/商品的服务器 ID 关系无法验证，会停止而不是猜测映射。没有对用户的真实后端发送测试数据；还需真机端到端核对。

项目继续保留 Draft PR #63，不合并主分支，不触发 Android 发布。GitHub 更新说明只保留当前版本。
