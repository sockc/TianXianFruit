# 天鲜账本 iOS V0.3.0 — 测试营业金额更正与云端版本冲突保护

适用于 iPhone X / iOS 16.6 / TrollStore（最低 iOS 15）。版本 **0.3.0 / build 15**，Bundle ID 保持不变。**仅覆盖安装，不要卸载旧版**，以保留本机草稿、提交任务和专用 Keychain 会话。

## 本次更新

- 新增「更多 → 测试账本营业金额更正」，可对已经同步的 `iOS_TEST_` 测试账本营业记录修改微信、支付宝、现金、费用及开/收摊库存估值。正式账本没有写入权限。
- 保留日期、位置、收款人、费用付款人、客户数、采购数据、凌晨收款及所有结算数据；不开放营业删除或采购编辑。
- 与 Android 保持相同的日期+稳定位置 ID 生成的 MD5 UUID v3，沿用该笔营业的 `sync_id`，只支持唯一、未删除且带稳定身份的记录；旧别名、墓碑或同日同位置重复数据一律拒绝更正。
- 按 Android 原公式核对营业额和利润；对可明确归属到单一收款人的渠道，按金额变更原 `receipt_splits_json`。同一渠道原本多人收款时不推测分摊比例；该渠道金额变更仍须在 Android 编辑。
- 提交前用独立的 USER 单账本测试账号重新核验权限，完整回读云端原记录的所有字段、版本号及同日同位置唯一性；创建 `row_version + 1` 的条件更正并在真正出网前再次读取云端确认。
- 原记录与变更记录、账号和目标账本范围、状态在发送前持久化到隔离 SQLite。网络超时或云端冲突后禁止盲目重传，只允许只读回读；服务端 ACK 后还须核验版本、金额、收款归属。
- 新增多项 XCTest 用例覆盖金额利润计算、稳定 ID、版本变化、云端删除、历史重复、多人收款、非测试账本以及本机提交队列不可变性。

## 简化测试

iPhone 与 Android 都使用同一 `iOS_TEST_` 测试账本。Android 先录入并同步一笔带明确收款归属的小额营业；iPhone 同步后在「更多 → 测试账本营业金额更正」打开相应记录，试将现金从 40 元改为 45 元并确认。iOS 云端回读完成后，Android 再同步并核对金额。出现冲突、网络中断或不确定结果时，**只点“只读核对云端”，不要重发**。

## 安全边界

iOS 仍不会修改 Android 项目、正式服务端源码或当日结算计算逻辑/UI。服务端当前的实际行级权限隔离与事务级 CAS 语义尚未独立验证，客户端的在线对比及 `row_version` 不能代替服务端原子并发控制。**只在不含真实经营数据的测试账本试用**，正式账本和安卓生产数据不参与。GitHub 的自动编译/模拟器测试不等于 iOS↔Android 真机端到端验证。
