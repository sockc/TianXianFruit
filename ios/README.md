# 天鲜账本 iOS V0.6.6 · Build 43 — 结算功能第三阶段（测试账本安全准备）

## 本版已经实现
- 测试账本工作台「利润分配与资金结算」现已连接到专门的结算操作准备页，并在测试账本的结算表添加入口；正式账本不显示操作入口。
- 支持选择营业日期、已同步的当日结算转账、部分结算、全额结算、恢复未结三种核对动作。输入目标累计已结算金额，与原云端方案金额和原已登记金额并排核对，金额输入采用与安卓相近的点击全选和完成键。
- 可在本机创建一次性核对单，记录测试账号、账本 ID、营业日、原始日结 sync_id、原始转账 sync_id、双方的 row_version、当前与目标登记金额以及单独的操作 UUID；支持复制到剪贴板交叉核对。这份核对单不进入服务器、同步脏队列或持久化结算数据。
- 严格拒绝正式账本、离线授权、只读成员、已删除账本、缺失/冲突的日结快照、无效金额（超额、负数、超过两位小数）、不变金额，以及错误日期的转账。云端同步变化后旧核对单自动清空。
- 生成日结方案、结清截至今日、利润分配已在测试操作列表中预留真实入口，明确说明这三种功能需要服务端计算资金中心与累计余额，不能从 iOS 客户端自行推算。
- 自动测试覆盖模拟原始记录、部分/全额/恢复未结、版本戳、权限隔离、重复金额、历史日期不匹配与原始行版本变化。

## 阶段说明：尚未开放实际结算写入
Build 43 是第三阶段的客户端准备部分，不是已完成资金写入的版本。当前已连接的 GitHub 仓库仅包含 Android/iOS 项目，没有服务端资金事务源码，正式 API 当前仅明确暴露原子营业、采购写入。

在服务端推出并验证 iOS_TEST_ 专用结算事务后，才能继续接入真正的写入执行、超时查询、跨设备冲突保护和安卓资金余额回读；不能通过通用 /sync/push 修改 settlement_transfer、settlement_partner 或 daily_cash_settlement 以伪造结算。因此本版本中提交按钮始终锁定，无资金结算 POST，也不改变安卓当日结算计算和正式账本。

## 安装与验证
从 GitHub Actions 下载 TianXianFruit-iOS-v0.6.6-Build43-TrollStore。iPhone X / iOS 16.6 使用 TrollStore 覆盖安装上一版本，勿卸载 App，以保留营业采购草稿及幂等提交锁。此次无需升级服务器。
