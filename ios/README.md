# 天鲜账本 iOS V0.8.0 · Build 49 — 三大核心操作入口

## 本版变更

- **首页直达营业、采购、结算**：不再让客户分析、报表和测试功能占据核心操作入口；底部原有模块与“更多”仍保留。
- **营业录入少一步**：在线且拥有服务端原子写入授权的 `iOS_TEST_` 测试账本，可直接点击“保存并同步营业”。先保存本机草稿，再按原有不可变操作编号进行提交、回读；失败不丢草稿，不自动重发。
- **采购录入优先显示**：日期、计划/完成金额、明显的“新增采购”和本机待同步单据在前；较长的采购计划与已完成明细可折叠，仍能从待采购计划带入实际采购。测试账本保存采购后直接弹出原有云端提交确认，无需回列表再点上传；取消确认仅保留草稿。
- **结算聚焦单日**：默认显示所选营业日，日期范围与位置/合伙人筛选收起；对已保存转账的调整入口不再暗示可以创建新结算方案。对单笔转账自动预选，默认“全额结算”，仍需核对和确认。
- **版本与打包**：版本 0.8.0 / Build 49，保留 iOS 15+、iPhone X / iOS 16.6 / TrollStore 覆盖安装兼容目标；工作流生成新命名的 IPA。

## 仍未开放的能力（必须如实显示）

- **正式账本营业和采购写入未放行**：V1.0.31 现有安全接口仅给在线、授权的 `iOS_TEST_` 账本写入；正式账本保存仍是本机草稿，不计入安卓收入、采购或结算。不能因界面升级就视为正式云端提交成功。
- **结算不重新计算**：仅可对服务端已保存、可核验的测试账本日结转账做部分、全额、恢复未结操作；没有权威日结时不猜测生成方案。正式账本原资金数据、Android 的计算算法、同步元数据与操作锁均不变。
- 不新增生产写入路由、数据库迁移或上传方式；真正的正式账本闭环还需要服务端兼容性和安全准入开发。

## 安装与核验

在本分支 GitHub Actions `Build TrollStore IPA` 成功后，下载
`TianXianFruit-iOS-v0.8.0-Build49-TrollStore` 工件，用 TrollStore **覆盖安装，不要卸载旧版**。
本版优先验证测试账号的三条日常操作链：营业录入→安卓可见，采购录入→安卓可见，以及有既存日结转账时的结算变更。其他回归由已有 CI 自动执行。
