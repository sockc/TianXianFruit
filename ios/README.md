# 天鲜账本 iOS V0.2.5 — Android 六项采购核对与云端变更保护

适用 iPhone X / iOS 16.6 / TrollStore，最低 iOS 15。Bundle ID 为 `com.tianxian.fruit.ios`，版本 0.2.5 / build 10。**只覆盖安装，勿卸载或清理应用数据**；保留历史营业/采购草稿、云端只读缓存和已保存的测试采购上传状态。

## 本版新增

1. **Android 六项人工核对表单**：当一笔 `iOS_TEST_` 采购的订单及单商品明细在服务器已完整回读后，打开“填写 Android 实际六项数据并验收”。必须在 Android **同一测试账本**独立查看并手动填写采购日期、采购人、商品名、单位、数量、总价；输入框不从 iOS 预填。六项任意一项不同或缺失，则无法标记人工验收。
2. **两套证据分离**：云端 `/sync/pull` 的客观父子记录校验独立于用户自报的 Android 核对。仅当二者一致时才保存 `androidReview` 证据到本机 SQLite。此证据不代表 iOS 实际连接了 Android，也不是 Android 服务器签名。
3. **云端版本指纹**：将完整测试账本 ID、来源账号、上传专用账号、服务器域名、采购父子 `sync_id`、云端真实数字 ID、服务端行版本号，以及首次冻结的订单/明细 payload 组合成稳定 SHA-256 指纹，用于判断已验收采购是否仍对应同一套云端记录。指纹只是本机变更检测，不是权威服务端认证。
4. **后续采购更严格解锁**：V0.2.4 允许在“我已核对”按钮点击后记一条时间；V0.2.5 要求之前的每一笔采购同时满足**云端重新完整回读一致、六项人工输入完全匹配、指纹未变化**，才能准备下一笔。旧版的单击确认时间仍保留，但不能直接充当六项验收；需重新查看 Android 并填表。
5. **防伪造和覆盖**：一旦本机存储 `androidReview`，后续不能删除、更改旧填写数据或强行替换指纹。若云端服务端行版本/数字 ID 变更，页面提示核对证据失效并阻止自动解锁下一笔；不自动更改服务器记录。
6. **审查窗口**：必须在最近 45 分钟的完整云端回读后进行 Android 验收。回读太旧，要求先点“刷新云端对账（仅查询）”。
7. **新增 9 项回归测试**：正常六项验收、数量金额异常、日期采购人商品单位差异、空字段或异常小数、回读过期、服务端行版本/ID 变更、旧版单击确认无效、SQLite 重启保持与不可覆盖、旧草稿 JSON 缺字段仍可读取。

## 保持原来的保护

- **仍仅允许现有服务器 `https://sync.830888.xyz` 上的专用 `iOS_TEST_` 测试账本**；专用普通 USER 账号必须恰好只看得到该账本，并有 OWNER/EDITOR 权限。客户端权限检查不能代替服务端实际对 token/book_id/父子记录归属的验证。
- 测试账本**本机最多准备 3 笔单商品采购**。每笔都必须由用户明确点击发送，前一笔完成云端和 Android 核对才能解锁后一笔。不得把正式账本改名作为测试账本。
- 真正业务写入只发生于独立采购测试传输类，普通 iOS CloudAPI 继续只读；**营业、凌晨收款、库存利润、客户账单、资金结算均不允许写入**。
- 继续支持服务器重新分配的采购订单父数字 ID，父子关联 ID 在发送商品明细前持久化；发送过的商品明细结果不确定时不自动重发；服务器 DELETE 墓碑不视为新单可重用的 ID。
- 没有修改 Android 的当日结算 UI、利润计算或其他业务代码；没有修改生产服务端源码与 APK 发布工作流。本 PR 继续处于 Draft 状态，不合并 main。

## 在 iPhone X 测试

1. 从 GitHub 成功 Actions 的 Artifacts 下载 `TianXianFruit-iOS-v0.2.5-TrollStore`，解压后通过 TrollStore **覆盖安装**。
2. 登录并打开名称以 `iOS_TEST_` 开头的独立测试账本，保留此前本机草稿。进“更多 → 采购逐项验收”。
3. 用只具该测试账本权限的专用普通测试账号进入测试采购同步。对已提交且云端确认的那一笔点击“刷新云端对账（仅查询）”。
4. 打开 Android 上同一个测试账本，核实同一订单和商品明细。在 iPhone 的“填写 Android 实际六项数据并验收”中**独立输入**采购日期、采购人、商品、单位、数量和总价。
5. 试故意输入错误数量或金额，应被拒绝。填写正确并保存后重启 App，再连接测试账号刷新云端，验收记录应仍存在。若云端订单版本/父子 ID 变更，旧验收应提示失效，且阻止下一单。
6. 仅在前一单云端和 Android 人工核对都通过后，才能继续最多三笔单商品采购。本版仍不支持正式账本或多商品采购写入。

## 目前边界

**本版不声称已在用户真实 iPhone 和 Android 上完成采购端到端验收**。人工输入是为了形成可核对的本地验收记录；不是自动获取 Android 数据。当前 CI 编译和测试结果也不能代替服务器端强制账本权限核查。上线正式采购写入前仍需要服务端权限、跨账本引用和数据库备份验收。
