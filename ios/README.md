# 天鲜账本 iOS V0.4.1 — 采购云端防重核对与有效进价参考

**版本 V0.4.1 / Build 21**。适用于 iPhone X / iOS 16.6 / TrollStore（最低 iOS 15）。Bundle ID 未变。请用 TrollStore **覆盖安装，不要卸载旧版**；本机采购草稿、登录、已保存缓存和原测试数据不会被主动清理。

## 本次实际新增

- **采购草稿一键核对云端**：底部「采购 → 本机采购录入」每条草稿右侧增加「核对云端」。iOS 先对当前正式账号和账本进行一次完整同步，随后按采购人稳定云端 ID、采购日期、每种商品的稳定 ID／数量／单位／真实单价／商品金额、整单金额，对比正式 `purchase_order` 和 `purchase_item`。区别以下四种结果：
  - **云端已有完全一致订单**：提示关联的正式订单已存在，防止用户在 Android 再次录入。
  - **同日同采购人疑似重复**：发现其他订单但金额/商品不全相同，提示核对，不自动覆盖。
  - **最新云端未发现**：明确仍是本机未提交记录，**不代表创建成功**。
  - **资料不完整，无法核对**：采购人/商品身份失效、父订单本地数字 ID 冲突、网络/离线缓存不完整时停止断言。
- **采购历史进价参考**：在新增/编辑采购的商品行，按已同步商品稳定 ID + 单位读取最近已存在正式订单的**有效非零单价**。零价采购、历史已删除商品、订单 ID 冲突均不作为进价来源。只显示「历史有效进价」及「填入」按钮；不主动覆盖实际手填单价，旧稿中的 0 值也不污染历史参考。
- 保存本机草稿前，额外校验已同步采购人及商品的**稳定云端身份与名称一致**。零单价仍允许录入；整单金额只由真实商品明细单价×数量得到，不拿采购订单总金额反算单件单价。
- 创建 8 项自动回归：已存在完全相同的订单、同日期金额不同、明细缺失、采购人/商品身份失效、父订单数字 ID 冲突、草稿指纹稳定性、零价过滤和历史价格归属。正式账本仍使用现有账号，无须重新创建测试账号/ID。

## 云端写入目前尚不能开放（重要）

本版**尚未把采购草稿提交到正式云端**，也不能在 iPhone 上完成或删除安卓采购计划。原因不是前端按钮，而是当前可访问的 `TianXianFruit` 仓库只有安卓客户端和服务端管理脚本，**缺少生产同步服务本体代码**。旧 `/api/v1/sync/push` 的单表收发不等于安卓完成采购时所需的多表原子事务；直接挪用会有重复订单、只上传部分商品及结算数据滞后的风险。

已写明需要的接口契约：[`ios/PURCHASE_COMMIT_CONTRACT.md`](PURCHASE_COMMIT_CONTRACT.md)。其核心条件是服务端按账号/账本校验权限、为同一操作强制幂等、校验期望行版本、将主订单／商品明细／计划完成及派生结算状态作为**一个事务**提交，网络失败通过操作 ID 查询结果而非盲重试。

**没有服务端事务实现之前，V0.4.1 的「核对云端」是读取，不是提交；显示历史一致订单亦不表示该草稿是 iOS 自动上传的。** 此次没有更改 Android、现有服务端或安卓当日结算算法、UI、字段及转账规则。

## 后续开发顺序

先完成正式采购的服务端原子提交与 iOS 不重复写入（可复用现有采购 UI、商品明细及本机草稿）；再继续营业页面完整编辑与凌晨收款；最后对接安卓资金结算。无需额外手工测试账号流程，保留自动编译及回归。

## 安装入口

GitHub Actions → `Build TrollStore IPA (no Apple certificate)` → 与此最终提交匹配的 `TianXianFruit-iOS-v0.4.1-TrollStore` 产物，解压后直接 TrollStore 覆盖安装。
