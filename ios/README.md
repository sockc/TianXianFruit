# 天鲜账本 iOS V0.4.2 — 采购导入库存与待采购计划

**版本 0.4.2 / Build 22**。适用于 iPhone X / iOS 16.6 / TrollStore（最低 iOS 15），Bundle ID 不变。请用 TrollStore **覆盖安装，不要卸载旧版**，以保留旧版本机草稿、登录与云端缓存。

## 本版新增

- 正式采购录入页面在采购人下方加入「导入库存 / 待采购计划」，多选商品后一次性导入到本机采购草稿；不需要测试账本或新的账号。
- 上次库存：读取不晚于所选采购日期的最近库存快照，核对商品稳定云端身份和单位，显示上次剩余数量作参考。**新采购数量默认 1、单价默认 0**，不把剩余库存当成今天买入的数量。
- 待采购计划：按所选采购人读取当天待采购商品（未指定采购人的计划也可以选择），保留计划数量、单位、规格重量及原计划明细同步 ID。**预计金额不用于反算单品单价**。
- 勾选、多选、全选；导入重复商品/单位会跳过，不覆盖已有草稿；总商品上限仍为 30 行。
- 旧采购草稿格式兼容。手动改动商品或单位时清除原计划关联，避免以后把其他商品误标为完成采购。
- 增加正式采购事务提案的客户端准备逻辑：唯一采购人和商品 ID、计划状态与协作状态、行版本 CAS、精确到分的商品成本、可重复计算的 SHA256 业务指纹，拒绝过期计划、跨日期和混合计划来源。
- 保留 V0.4.1 云端订单防重核对、历史有效非零进价和安卓式日期/已完成/待采购视图。新增自动回归，用户不用逐项重复手工测试。

## 安全边界

**正式采购云端创建、完成采购、修改或删除仍未开放。** 当前可访问的 TianXianFruit 仓库不包含正式服务器的完整后端源码，无法实施/验证完整的原子多表采购事务（采购主单、商品明细、计划状态、协作金额和财务派生记录）。因此 V0.4.2 只准备事务提案，**绝不直接发送到正式服务器，也不把本机草稿并入安卓利润或结算**。

服务端接入要求详见 ios/PURCHASE_COMMIT_CONTRACT.md：必须在实际服务端落实账本权限、幂等操作 ID、版本 CAS、多表事务回滚、结算联动及超时只读查询。此次没有修改 Android 当日结算逻辑/UI，也未改现网服务端。

## 使用

现有账号登录 → 底部「采购」→ 选择日期 → 添加商品/采购录入 → 先选择采购人 → 导入库存或待采购计划 → 选择商品 → 校对实际数量和单价 → 保存本机草稿。

安装时使用 GitHub Actions 中当前最终提交对应的 TianXianFruit-iOS-v0.4.2-TrollStore 产物。
