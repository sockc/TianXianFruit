# 天鲜账本 iOS V0.2.6 — 多商品采购录入与草稿编辑

适用 iPhone X / iOS 16.6 / TrollStore（最低 iOS 15）。Bundle ID `com.tianxian.fruit.ios` 不变，版本 0.2.6 / build 11。**覆盖安装即可，切勿卸载或清除 App 数据**；已有采购、营业草稿及云端测试任务继续保留。

## 本次更新

1. **独立多商品采购编辑器**：在「更多 → 写入测试实验室」解锁 `iOS_TEST_` 账本后，选择采购，点击「新建多商品采购单（推荐）」；一张单可加入最多 **30 条商品明细**。每行独立选择已有商品，填写数量、单价、单位（如斤/件/箱/袋）和每件重量，按“数量×单价”计算本行小计。
2. **整单金额精确核算**：数量最多三位小数、单价最多两位小数，使用 `Decimal` 计算并对每行小计按分四舍五入，再累加得到采购合计。支持 0 元进价，拒绝负数、非法字符、金额越界、缺少商品/单位、重复行 ID 和合计不符。
3. **本机草稿编辑、复制与删除**：未绑定云端上传意图的采购草稿可以修改日期、采购人、商品、数量、单价、备注并保存；支持复制为全新草稿（新草稿 ID、明细 ID），或删除。**已经绑定云端同步任务的草稿被冻结，不可修改/删除，但可复制**，以免破坏原有上传身份、金额和冲突处理。
4. **旧版单商品兼容**：原单商品草稿仍可继续读取和使用旧版测试同步；打开新编辑器时以一行进行预览，旧记录在点击保存前不会改变。如果历史的“数量÷总价”涉及单价舍入，界面提醒人工核对原总价。
5. **离线重启可恢复**：多商品明细保存在现有独立本机 SQLite 的草稿 JSON 中，用账号+测试账本隔离。切换账号/账本不展示另一个账号的草稿，重启后保持商品列表、录入日期、总金额和草稿身份。
6. **多商品云端写入仍锁定**：当前服务端与 Android 采购订单父子数字 ID 映射尚未完成“一单多条明细”的真实端到端验证。新 `purchaseItems` 草稿**只可本机保存**，**不会调用 `/sync/push`**。V0.2.6 的旧单商品测试上传流程继续按原规则逐笔确认，最多三笔测试账本订单，维持 Android 六项人工验收。上传页会明确显示「多商品草稿仅限本机」，避免误传第一条商品。**不要把本版描述成已实现多商品云端同步**。
7. **专项回归**：新增九项测试覆盖三商品 ¥240 计算、逐行分级舍入、件/斤数量、非法价量和重复明细、整单金额防篡改、旧 JSON 解码、上传门禁、SQLite 重启与编辑/复制、已绑定上传任务的草稿不可修改删除。

## iPhone X 验收步骤

1. 在 GitHub Actions 成功的 `Build TrollStore IPA (no Apple certificate)` 中下载 `TianXianFruit-iOS-v0.2.6-TrollStore`，解压后 TrollStore **覆盖安装**。
2. 切换到独立 `iOS_TEST_` 账本，进入「更多 → 写入测试实验室」，手动输入账本完整 ID 并勾选确认。
3. 选择「采购草稿」，点击「新建多商品采购单」，选择采购人并添加 **无籽红提 20斤×¥3.50，苹果 30斤×¥4，香蕉 25斤×¥2**，整单合计应为 **¥240.00**。
4. 保存草稿并关闭 App，重新打开后确认三条明细、采购人、日期、数量和金额完整保留；进入编辑修改一条价格，预览合计应立即变化，保存后再检查。
5. 复制为另一笔草稿，确认原草稿不变。尝试删除未上传的草稿应仅在本机生效。
6. 打开「采购同步与对账」：多商品草稿应明确显示**暂不可上传**；旧版单商品测试订单仍按之前的保护机制运行，不能自动批量提交。
7. 认真核对 Android 正式账本的采购、库存、营业额、利润、凌晨收款和当日结算未被改动。

## 不变的安全边界

- 原正式后端地址仍为 `https://sync.830888.xyz`。仅测试账本专用普通 USER 账号可在独立入口试写**旧版单商品**测试订单；通用 iOS `CloudAPI` 只读。
- 本次**不修改 Android 源码、正式后端、原有 APK 工作流或当日结算算法与 UI**，更不支持正式账本写入、营业、凌晨收款及资金结算操作。
- 多商品从本机草稿升级到真实云同步，必须首先验证服务端 `purchase_order` 与多个 `purchase_item` 的幂等重试、跨设备 ID 重映射、删除及金额归属，再做单独版本的安全开放。
- 本 PR #63 继续为 Draft，不合并 main；GitHub 更新说明仅保留 V0.2.6。
