# 天鲜账本 iOS V0.2.9 — 测试账本营业新增同步

适用 iPhone X / iOS 16.6 / TrollStore（最低 iOS 15）。版本 0.2.9 / build 14，Bundle ID 不变，**覆盖安装，不要卸载旧版**；保留原有草稿、已开始的上传任务和专用 Keychain 会话。

## 本次更新

- 新增「更多 → 测试账本营业同步」。只接受 `iOS_TEST_` 单独测试账本及普通 USER、只能看到该测试账本的专用测试账号；每次上传前在线验证权限。正式账本全部业务写入仍锁定。
- 在「写入测试实验室」保存营业草稿，选择营业日期、位置、微信/支付宝/现金、各渠道收款人、费用付款人及开/收摊库存估值。
- 显式点「上传测试账本」才提交一张新的 `store_daily_record`。采用 Android 现行「日期 + 稳定位置同步 ID」对应的 Java UUID v3 身份，绝不另造随机云端营业别名。
- 多收款人分组生成完整 `receipt_splits_json`，渠道总额与归属一致。营业利润与安卓源记录公式一致：**营业额 + 收摊库存 - 开摊库存 - 费用**。营业记录里的 `purchase_cost` 沿用安卓的 0，采购金额由独立采购表管理；草稿里采购金额只是本机参考，不参与营业上传。新老顾客本版为 0。
- 每次提交前拉取全量测试账本数据，遇到同日同位置已有记录、旧别名或删除墓碑一律禁止新增。上传意图先写入独立本机 SQLite，任何可能已经发送的营业绝不盲目重试。
- 每次上传的成功判定需要服务端 ACK，之后只读回读并核对金额、收款归属和稳定身份；超时、冲突或异常只能点「只读核对云端」，不会直接重复发送。
- 新增 6 个专项回归：Android 稳定 UUID、多人收款/利润、同日同位置冲突、错误回读、草稿锁定与不可逆请求状态、非测试账本隔离。

## 简化验收

在 iOS 选择 `iOS_TEST_` 测试账本，进入「写入测试实验室」保存一条少量金额营业草稿，再到「测试营业同步」点击一次上传。安卓同一测试账号同步后核实该条营业。如果网络超时，**不要重做同日同位置记录或点击重传**，仅使用「只读核对云端」。

## 保护范围与局限

不修改 Android 项目、后端和当日结算的逻辑或 UI，不开放正式账本营业写入、营业编辑/删除、凌晨收款、利润分配和资金结算。服务端测试账号范围核验**不是**服务器跨账本行级安全审计，也不证明服务端实现原子 CAS/唯一性。请仅在不含真实营业数据的测试账本中进行小额试写；GitHub 自动编译/模拟器回归也不能代替 Android↔iOS 真机同步验证。
