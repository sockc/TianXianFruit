# 天鲜账本 iOS V0.2.7 — 简化测试账本采购同步

适用 iPhone X / iOS 16.6 / TrollStore（最低 iOS 15），版本 **0.2.7 / build 12**，Bundle ID `com.tianxian.fruit.ios` 不变。**只覆盖安装，不卸载、不清理应用数据**；旧版本机草稿、上传队列以及已有 Android 人工确认记录保持可读。

## 本次变化

1. **无需每次填写密码与账本 ID**：在 `iOS_TEST_` 账本首次用专用测试普通用户验证一次，之后该账本专用 access token 保存到**本机 Keychain (WhenUnlockedThisDeviceOnly)**。每次进入“采购同步”先自动恢复登录，并在线重新读取 `/auth/me` 和 `/books` 确认权限；令牌失效或管理员/多账本权限不符才提示手动登录。**不保存密码**，不复用正常 App 的登录令牌，按本机原登录账号+测试账本 ID 独立存储。可以在同步页面点“更换账号”清除测试令牌。
2. **不再手动输入完整账本 ID / 每次勾选确认**：测试账本由当前选中的账本自动识别，只认名称以 `iOS_TEST_` 开头、状态可用、权限可编辑、ID 完全匹配的账本；专用测试登录必须是系统普通 USER 且可见账本恰好一项。客户端必须在真正每次发出采购变更前重新核验服务器账号和账本范围。
3. **采购单一键同步**：在“更多 → 写入测试实验室”新增/编辑本机采购草稿后，进入“更多 → 采购同步”，点击该单“上传测试账本”即可**一次操作依序完成准备、订单上传、所有商品明细逐条上传及回读**；不再“准备 → 上传 → Android 六项填表 → 下一单”等多轮流程。云端正常回读时直接显示完整商品数量和成功状态。
4. **多商品采购云同步**：支持 V0.2.6 新版 `purchaseItems` 草稿。一张订单只创建一个 `purchase_order`，每条商品创建一个稳定 `purchase_item` 同步 ID 与本地数字 ID，保留采购数量、单位、实际单价、每件重量及按分舍入的小计；全部商品金额之和必须与订单总价一致。订单先写入并回读服务端权威数字 ID，再将这个 ID 作为每条商品的 `order_id` 顺序提交，**不会只上传第一行**。
5. **取消三笔上限与强制 Android 六项人工验收**：已完成的历史采购不再每次重新逐笔检查金额（Android 可能合法地修改历史采购）；仅有**未完成或结果不确定的本机上传任务**会阻止新单。每张新订单仍需在线核验专用测试账号权限、当前采购人和商品映射，并在上传后完整回读。Android 可首次或异常时抽查，不代表 iOS 自动读取 Android 本机数据。
6. **不确定结果不自动重传**：每条商品请求发出前，先在本机 SQLite 冻结其已尝试发送的同步 ID；超时/断网/进程中断后若云端未确认该条，停在异常并显示“只读核对云端”，不会自动重发可能已经被服务器接收的商品。只有确认其他尚未发送的商品才允许继续。云端重复、错挂父订单、总额不符、DELETE 墓碑或跨账本异常均拒绝自动继续。
7. **旧单商品兼容**：V0.2.2–V0.2.6 老订单与草稿仍用原 `itemSyncID` 格式，新增多商品相关字段为可选值。保留 V0.2.6 的本机草稿编辑/复制/删除、已提交草稿不可修改/删除保护。
8. **安全边界不变**：只使用 `https://sync.830888.xyz` 和独立测试账本的专用单账本普通用户；普通 `CloudAPI.swift` 仍没有业务写入 API。**不开放正式账本营业、采购、利润、凌晨收款或资金结算写入**，不修改 Android 当日结算逻辑、UI、正式服务端源码或原 APK 工作流。

## 一次验收示例

- 在 Android 与 iOS 用同一个测试账本确认能读取测试商品与采购人。Android 的**正式账本**无须参与本次试写。
- iPhone 在测试账本本机新增一张包含三种商品的采购草稿：无籽红提 20斤×¥3.50，苹果 30斤×¥4.00，香蕉 25斤×¥2.00，总价 **¥240.00**。
- 进入“采购同步”。首次输入测试账号和密码，此后通常自动登录（令牌过期需重新授权）；选刚才草稿点击一次“上传测试账本”。
- iOS 应显示 **1 张订单、3 条商品、合计 ¥240.00** 的云端回读结果；然后在 Android 打开**同一测试账本**抽查这张订单的三种商品和总金额。正常以后不必每单反复做完整人工验收。
- 如果出现“请求结果不确定/明细错挂/金额不一致”，先点击“只读核对云端”排查，**不要重新创建一张订单来补传**。

## 权限边界与真实环境限制

- **测试账号仅可见测试账本，不足以证明服务端绝对没有跨账本漏洞。** 服务端每次 `/sync/push` 都应校验 token、账本 ID、商品引用和每张父子订单关联。本 GitHub 仓库仅有客户端与部分 server-tools，**未核验生产后端全部写入实现**，不能保证“写错一定只影响测试账本”。
- 本次仅客户端更新和 GitHub 模拟/构建测试，**未替用户实际向服务器写采购数据或读取用户 Android 设备**。多商品采购的跨设备完整验收仍需首次成功后抽查一次。
- 不自动发起后台商业写入，网络请求只在用户主动点击“上传测试账本”或“继续同步”后发送。Keychain 自动恢复只是认证，不进行后台业务推送。
- GitHub PR #63 持续 Draft，所有 iOS 更新留在独立分支，不合并 Android 主分支。GitHub 更新说明仅保留 V0.2.7。
