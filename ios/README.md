# 天鲜账本 iOS V0.2.3 — 采购首单云端核对与可靠性

适用 iPhone X / iOS 16.6 / TrollStore（最低 iOS 15）。继续使用原 Bundle ID `com.tianxian.fruit.ios`，版本 0.2.3 / build 8。请直接覆盖安装，**不要卸载或清除 App 数据**，保留 V0.2.0–V0.2.2 的本机草稿与测试订单上传状态。

## 当前版本新增

- **云端对账状态**：使用专用普通账号在 `https://sync.830888.xyz` 的唯一 `iOS_TEST_` 账本读取 `GET /sync/pull` 完整数据，核对一笔采购的父订单 `purchase_order`、子明细 `purchase_item`，对比 `date/buyer_id/buyer_name/store_id/total_cost/remark/status/fruit_id/fruit_name/quantity/unit/unit_price/unit_weight_jin`。
- **跨设备数字 ID 重映射识别**：服务器可能把发送端的本地数字 `id` 重映射，回读时以稳定 `sync_id` 找到服务端权威父订单，再核对明细的 `order_id` 是否指向**服务端实际**父订单 ID。若父订单 ID 已变但子明细尚未发送，**停止继续上传**，不使用旧 ID 冒险生成无主采购明细。
- **重复商品明细检测**：同一父订单只有一条有效商品明细才认为当前单商品采购完全一致；多条/错挂订单、金额/数量/采购人/商品/单位差异、删除墓碑/缺失记录均列出详细核对项。
- **上传前重复检查**：点击测试上传前先读取同一测试账本云端快照。如果同 `sync_id` 的订单或明细已存在，**不会再次推送**；保留本机需人工核对的状态。上传中仍严格“订单 ACK+回读 → 明细 ACK+回读”，网络超时/冲突不自动重发。
- **明确区分云端与 Android**：云端服务器对账通过不代表 Android 设备已经同步。新增只读“刷新云端对账”按钮；只有云端父子一致且本机记录为完成时，用户才能点击“我已在 Android 核对”保存**人工验收时间**。人工验收仅写本机 SQLite 草稿数据库，不会触碰服务器。
- **旧记录兼容**：给上传意图添加可选人工验收时间，旧版 JSON 数据仍可解码。保持同账号、同账本的本地订单身份及金额不可更改。
- **中断和切换防护**：账号或账本切换会使异步上传链路失效；已经发出的网络请求可能到达服务器，但不会因换账本而继续发送第二条记录。本机保留待核对状态。

## 保持的保护

- 仅固定官方 HTTPS `sync.830888.xyz`，不能指定任意服务端。
- 必须使用**独立普通 USER 账号**，其 `GET /books` 必须**恰好只有一个**与本机草稿 ID/名称完全一致的 `iOS_TEST_` 测试账本，role=OWNER/EDITOR；每次推送前重新核对。
- 一账本仍仅允许一笔单商品采购验证任务；不解锁批量采购、营业/凌晨收款/利润分配/资金结算写入。通用 `CloudAPI.swift` 仍无业务 POST push。
- 不修改 Android 当日结算逻辑/UI、正式后端源码或 APK 构建工作流，继续在独立 iOS PR 草稿分支。
- 客户分析、天气和报表、旧离线缓存与本机草稿保持可用。

## 建议真机验收

1. 创建或选中一个从未用于正式交易的 `iOS_TEST_` 账本，测试账号必须只看到此账本。**不要将正式账本改名当测试账本。**
2. 打开“更多 → 采购首单核对”，先使用专用测试账号登录并验证账本范围。
3. 有本机采购草稿时，先核验商品/采购人引用并准备单笔测试上传。若此账本已有上传意图，直接查看状态，不要重新准备。
4. 成功上传后选择 **刷新云端对账（仅查询）**，核对订单、商品、数量、金额、父子 ID 和所有不一致提示。
5. 使用 Android 登录同一个测试账本，确认订单及其单个商品明细都可见，金额和单位完全一致，再点“我已在 Android 同一测试账本核对…”记录人工验收时间。
6. 测试断网、重启、服务器部分成功、冲突和多次点击。出现“结果待核对”时先查询远端，**不要猜测不存在就重复推送**。
7. 最后核对 Android 正式账本的采购、库存、当日结算、利润和凌晨收款没有任何变化。

## 技术验收与限制

- 新增 `PurchaseReadbackAudit.swift`、`PurchaseReadbackAuditTests.swift`：模拟父子完整匹配、服务器重映射、错挂订单、重复明细、金额/数量/单位/采购人差异、墓碑、缺失、旧版草稿解码、人工验收标志持久化。
- **本版本并未替用户在生产后端实际写入测试数据，也未自动访问 Android 设备。** GitHub CI 的模拟回归不能替代真实服务器/Android 端到端验收。
- 重要：**客户端的单账本检查不能代替服务端 `/sync/push` 对 token、book_id、记录归属的授权。** 真正试写之前务必确认服务端在服务端层隔离账本，建议先备份并执行只读权限测试。
- 这版对已被服务器重映射的父订单数字 ID **只识别并报告**，不会自动改写冻结的商品明细 payload。若出现这一情况，停止后续写入以便专项确认映射协议。
- 当前 GitHub 仅保留 **V0.2.3** 更新说明，IPA 由 Actions 工件提供，不合并主分支以免触发 Android 发布。
