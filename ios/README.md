# 天鲜账本 iOS V0.3.3 — 营业多收款人逐人更正

版本 **0.3.3 / Build 18**。适用于 iPhone X / iOS 16.6 / TrollStore（最低 iOS 15）。保留原 Bundle ID，**请用 TrollStore 覆盖安装，不要卸载旧版**；旧版 SQLite 测试草稿、已提交任务和测试 Keychain 令牌保留。

## 本版新增

- 「更多 → 测试账本营业更正 · 多收款人」增加**按原收款人逐人输入微信、支付宝、现金金额**。同一支付渠道由多人收款时，不再按比例猜测，只有明确输入每个人的金额才会上传。保留日期、实际位置、收款人身份、费用付款人、顾客和原营业同步 ID。
- 输入金额须合法、精确到分；每位原收款人仍须存在且合计大于零，不允许悄悄增加、移除或改名。原始收款明细必须与各支付渠道合计完全一致，否则拒绝覆盖。
- 同渠道收入**合计不变但在两个原收款人间重新分配**也视为真实更正，并保存到 `receipt_splits_json`；复核原来的 `revenue` 与 `profit` 计算，费用和开/收摊库存估值沿用此前规则。
- **已出现利润分配、资金结算、结算转账或利润结清历史的自然营业日一律阻止 iOS 营业更正**（包括历史删除墓碑）。安卓编辑营业时会同步作废相关派生结算记录，但 iOS 没有实现服务端事务级自动作废；因此本版宁可禁改，防止营业账和结算账不一致。
- 提交前两次核对独立测试账号身份、唯一营业记录、原云端版本和内容，发送前持久化唯一不可变任务。若原 iOS 新增营业仍存在未确认请求，禁止编辑同一营业记录；断网或冲突**只允许只读核对，绝不自动重传**。
- 保留原 V0.3.2「测试同步核对中心」与采购新增、采购备注修改、营业新增、只读经营/客户/资金分析功能；没有新增正式账本写入权限。

## 简化验证

1. 在 Android 的 `iOS_TEST_` 独立测试账本，创建一条**未做过利润分配或结算**的营业，设两个测试收款人（例如微信甲 50 元、微信乙 50 元，其他金额适当填写）。
2. iPhone 覆盖安装后，同步并在「更多 → 测试账本营业更正 · 多收款人」分别输入甲 60、乙 40，**微信总金额仍为 100 元**；确认提交一次。
3. iPhone 在「测试同步核对中心」查看云端更正是否匹配，Android 同步后查看两个原收款人金额。若显示冲突/断网，请只读核对，不要重发。

## 当前仍未开放的营业功能

- 营业删除、修改日期/位置、增加或删除收款人、跨自然日凌晨收款转移。
- 与正式后端事务级 CAS、结算失效处理及凌晨收款联动的写入，必须在完成后端安全审计后才可开放。
- 正式账本的所有 iOS 写入。

本次未修改 Android、正式同步服务端和当日结算计算逻辑或 UI。**本机金额与版本的两次核对不等于服务端原子并发控制证明**。仅在无真实经营数据的 `iOS_TEST_` 测试账本试用。
