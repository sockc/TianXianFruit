# 天鲜账本 iOS V0.4.3 — 正式采购原子提交与云端回读

**版本 0.4.3 / Build 23**，兼容 iPhone X / iOS 16.6 / TrollStore（最低 iOS 15）。Bundle ID 不变。**请覆盖安装，不要卸载旧版**，本机采购草稿、旧测试草稿、Keychain 和云端缓存维持原格式。

## 本版新增

- 底部正式「采购」继续沿用安卓风格：待采购/已完成、采购人分组、历史、上次库存和待采购计划导入、价格记忆、多商品录入及原云端订单防重核对。
- 新增正式服务器的只读「采购写入能力」检查。必须由 **V1.0.25+ 服务器**返回版本 1、enabled、atomic、idempotency 和精确的 feature ID 才允许提交；旧服务器、离线、缓存身份或未启用时，继续只保存本机草稿。
- 管理员在服务器明确启用采购事务后，正式采购草稿出现「提交正式采购」按钮。点击后确认金额；提交前完整刷新当前账本，并核对订单不存在重复或身份冲突。
- 为每笔草稿单独创建本机 SQLite 不可变提交保护记录：保留 **同一账号+账本+采购草稿 UUID**、规范化请求、金额及版本；提交后草稿被锁定，不能再次编辑/删除而造成重复入账。
- 请求通过已有正式账号 Token 和注册设备身份发送到专用 **POST /api/v1/purchases/commit**，绝不调用旧的单行 /sync/push 来冒充多表事务。
- 成功收到服务器回执后再次完整 pull，必须同时找到订单主单和全部商品明细且日期、金额、数量一致，才显示「云端已确认」。
- 网络异常或应用重启后只显示「查询原提交结果」；调用只读 GET /api/v1/purchases/operations/{operation_id}，不自动重试 POST、不生成新操作 ID；服务端回执或回读不完整时保留锁定及提示。
- 专项 XCTest 增加能力检测、永久操作锁定、重复操作 UUID 禁止新内容、网络未知状态恢复、收据和商品逐项核对。

## 服务器必要条件与现网默认行为

本版同步提供独立的 **TianXian-Server V1.0.25** FULL 与 PATCH 源码压缩包，基于资料库内 V1.0.24 完整源码新增服务器采购事务接口：采购主单、商品明细、采购活动、计划状态、协作金额和同步事件在一个数据库事务内提交；服务端验证账本真实权限、行版本和幂等操作 UUID；发现已有利润分配/资金结算日会拒绝直接修改。

**默认服务端开关 TIANXIAN_PURCHASE_COMMIT_ENABLED=false。** 源码升级包不是已经部署到线上。没有完成正式服务器安装、备份及 PostgreSQL 并发/安卓同步核验前，V0.4.3 的正式采购提交按钮不会出现，账本仍安全地只读云端。此版本不会改变安卓当日结算算法、页面、字段或转账规则。

安装服务器必须先确认现网实际运行版本 **V1.0.24**，使用提供的 DRY_RUN 模式核对、提前备份数据库；服务端脚本会再次 pg_dump 备份，自动恢复服务器源文件；不能自动在生产环境启用写入。**没有进行实际服务器远程部署，也没有对正式账本做过写入测试。**

## 用户操作

在 iOS 采购页选择日期、采购人、商品，导入上次库存或待采购计划，填写真实数量与单价，保存本机草稿。若管理员部署、核验并启用 V1.0.25 原子采购接口，提交按钮才会出现。点击确认后查看提交状态；异常时使用「查询原提交结果」即可，不必建立新测试账号。

服务端原子 API 契约见 [PURCHASE_COMMIT_CONTRACT.md](PURCHASE_COMMIT_CONTRACT.md)。
