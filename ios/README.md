# 天鲜账本 iOS V1.0.1 · Build 78

- 最低 iOS 15.0，TrollStore 安装；iOS 16 及以上支持自适应库存布局。
- 核心五页共用经营日期，中文日历、左右滑动，保留编辑器日期及草稿保护。
- 首页四色金额、采购和营业内嵌录入、库存五列、客户分析紧凑筛选及分页、结算预览及更多菜单。
- 商品总价通过显式确认反算单价，只有两位小数单价精确对应实际总价时允许填入；原提交校验不变。
- 结算预览绑定账本/日期/同步版本；保留原计算、授权、身份验证及原子提交。
- 键盘弹出隐藏底栏，长商品名与价格自适应，窄屏使用堆叠布局。
- 自动回归、XCTest、IPA 校验及用户实机验收通过；使用原 Build 78 安装包，不重新编译发布。
- Android V1.4.7.135 和服务端 V1.0.36 保持不变；凌晨扣减、费用付款人、账单导入、结算分享、协作采购等未纳入本版。
- [下载 Build 78 IPA](https://github.com/sockc/TianXianFruit/releases/tag/ios-v1.0.1-build78)

## V1.0.2 Build 79 开发候选（未发布）

第一阶段：复用现有客户增量同步的 OVERNIGHT 事件，按自然日与收款人只读显示昨日凌晨（选中日 D）及本次凌晨（D+1），不跟随位置，不自动计入/扣减营业额。明确区分未确认和确认零金额，拒绝重复或畸形来源。营业原子提交 v1 不支持凌晨来源、跨位置归属事务或费用付款人；在服务端源码和协议验证之前，不开放这些写入及补录联动。不改 Android、服务端、结算算法。

- 对照已部署版本 V1.0.36 RC3 源码：`/customer-analytics/changes` 必须显式传 `include_overnight=true`；能力 `overnight_rollover` 支持时启用。旧缓存游标首次完整回放，覆盖标记与账号、账本、游标、时间在同一 SQLite 事务提交，后续继续增量同步。服务端既有 `/push` 有单实体修订 CAS，但与营业原子 `/commit` 是独立事务；费用付款人目前写死为未指定。暂不合并写入路径。

- V1.0.37 RC1 预备协议：新增独立 V2 自然日金额计算及请求规范化、SHA256 跨语言固定样本 XCTest；不接入网络 POST，不改变 V1 营业提交、权限或草稿。服务器候选默认关闭且仅测试账本可用；需真实 PostgreSQL 双锁测试及独立 V2 outbox/两路回读后再接入保存。

- Build 79 第二阶段：隔离测试账本营业页新增独立凌晨/费用 V2 录入入口，保存本机独立草稿，显示自然日三渠道、昨日凌晨逐渠道绿色/红色扣减、本次凌晨登记及费用付款人。明确区分空值与零，使用实际来源修订号生成调整后营业和 V2 请求指纹。旧 V1 草稿存在时拒绝预览，账号/账本/日期/位置隔离；同步游标改变后清除预览。不调用 V2 网络写入，真实 PostgreSQL 验证及 V2 outbox/回读仍待完成。

- V2 草稿持久保存用户已核对的 D/D+1 来源版本；同步后修订号变化必须明确确认新版本，保留原录入值，禁止静默重基线。已有 NATURAL 来源禁止新建预览；不替换现有 V1 账务。

- V2 测试提交：仅测试账本、在线双流刷新与明确 V2 capability，生成内容一致后先 SQLite 独立不可变保留，再 POST 一次；断网/未知结果只 GET 原操作，不重发。回执验证原操作/哈希/收款人/来源版本；回读营业金额、付款人精确整数 ID、自然日三渠道及扣减/保存金额和凌晨来源版本。正式服务器 V1.0.36 无 V2 capability，保持禁用；V1.0.37 RC1 默认关闭，真实 PostgreSQL 验证未通过前不得启用。

- 原测试账本 V1 同日期/位置若已存在 V2 不可变保留，禁止新增本机 V1 草稿及 V1 新提交，正式账本不执行该检查。测试覆盖持久化保留、第二次保留失败、精确 64 位付款人 ID、来源缺失及游标不足回读失败。

## V1.0.2 Build 80 开发候选

Build 79 已完成六项实机验收，原 IPA 保留。V2 客户端以 V1.0.38 RC1 的 `test/formal/none` 回执严格匹配账本类型，权限未开放不允许 V2 POST，提交前重新查询。营业页按在线能力显示正常新增入口，V2 页面内录入同一行位置及营业时间、收款三渠道、凌晨扣减及费用付款人、保存营业确认；历史 V1 草稿继续使用原编辑器，V2 草稿及原操作从独立核对入口恢复，V1 禁止覆盖同范围 V2 草稿或保留。保持原 Build 79 草稿键和 SQLite 文件。无服务端线上修改、无结算变更；待 CI、V1.0.38 隔离验证与正式授权后实机核对。

- 本摊营业额实时预览复用与 V2 请求相同的调整收款行；缺成本只隐藏利润，不隐藏有效收款；未确认来源不显示虚构零金额。已锁定原操作展示原提交金额，保存确认提示日期位置及金额。已有草稿仅在恢复区显示，不重复列入新增入口。

## V1.0.3 Build 81 开发候选（独立分支）

正常营业表新增本机 CSV 账单预览。初步支持 UTF-8/UTF-16 BOM/GB18030，保留长交易号字符串，严格商家收款筛选、支付宝备注不作为经营证据、退款净额、Android SHA256 去重及客户键规则（仅有真实订单号及支持格式）。同交易号内容冲突拒绝；缺订单号/异常金额/日期计入待核对。收款人选择与自然日、次日 00 时观察、本机已同步交易键重合统计；不认定导出覆盖完整，不修改营业草稿、现金或客户交易，不上传。ZIP/XLSX、完整覆盖核对、营业与客户事务、凌晨归属仍待开发。Build 80 原分支和 IPA 不变。

- 第二阶段：支持同收款人多份账单预览（最多12份）、跨文件交易去重及源文件哈希关联、云端 RECEIPT/SOURCE_LINK/COLLECTOR 对照和删除/冲突/未知归属分类；自然日与次日00时分开展示。新增内存 ZIP/XLSX 读取，CRC 与解压上限验证，不落地解压文件，单账单/单工作表，拒绝公式和不可靠数字订单号。仍然没有营业覆盖、客户 push 或完整覆盖认证，待 CI 及真实账单实机验证。

- 第三阶段：完整自然日账单由用户逐渠道确认；缺观察记录、异常行、云端同收款人缺失交易、归属冲突、已删除交易和大额/手动排除待核对时禁止生成补录方案。只修改独立方案中的微信/支付宝自然日金额，原普通草稿、现金、扣减及凌晨输入保留。复用 V2 调整计算显示一次调整后金额；本机单独持久化原输入/候选、交易键/文件哈希与来源版本，不将候选写入普通草稿，存在独立方案时普通 V2 禁止提交，允许明确放弃恢复原路径。尚无客户联合写入或覆盖已存在云端营业；仅面向当前新增营业草稿。
