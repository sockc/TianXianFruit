# 天鲜账本 iOS V0.2.2 — 同服务器、独立测试账本采购同步

适用 iPhone X / iOS 16.6 / TrollStore（最低 iOS 15）。覆盖安装保留 V0.2.0/V0.2.1 已保存的本机草稿，**不要卸载旧版**。

## 重要边界

本版不用部署新服务器，也不要求额外的 `ios-test/attestation` 接口。现有独立后端地址与登录全部固定在：

`https://sync.830888.xyz`

但这 **并不意味着共享服务器的所有账本绝对安全**。客户端只能按服务器公布的权限、账本 ID 和记录回读做防护；**真正防止跨账本写入仍取决于服务端在每次 `/api/v1/sync/push` 对 token、book_id、变更行和所属资源进行强制校验**。本仓库没有后端完整实现，不能假称已验证服务端隔离。首次试写之前建议备份生产数据库，核实服务端权限，使用仅有测试账本访问权限的专用普通账号。

## V0.2.2 更新内容

1. **硬编码唯一 HTTPS 服务端域名**：采购上传独立客户端只能连接官方 `sync.830888.xyz`；拒绝任何其他域名、IP、HTTP、端口、带路径/凭据/查询的 URL，不可在 UI 改 URL。通用 `CloudAPI` 仍只有登录、只读 API，没有业务 push 功能。
2. **独立测试账号**：每次在上传页面输入仅供测试使用的普通账号密码，登录数据通过独立 URLSession 临时内存持有，不复用主登录的 Keychain 令牌、不写入云端账户缓存、不会自动再次发送凭据或重定向。
3. **严格账本门禁**：从测试账号的 `GET /api/v1/auth/me` 必须读到 `system_role=USER`；`GET /api/v1/books` 必须**恰好返回一个账本**，其 ID 和名称与当前本机草稿所属账本一致，名称以 `iOS_TEST_` 开头，账号角色为 OWNER 或 EDITOR。拒绝超级管理员、拥有正式账本访问权限的账号、角色不足或重名异 ID 情况。每次上传前再次读取账号和账本列表核对。
4. **首单限制**：当前一个测试账本仅允许准备**一笔**上传任务（订单+单个商品明细），不会放开批量上传。准备前从同服务器的测试账本拉取正式记录，按稳定 `sync_id` 检查采购人/商品，冻结对应数字 ID、订单与明细 `sync_id`、金额、数量及父子 ID。
5. **严格确认与回读**：订单先 `/sync/push`，收到与订单匹配的 accepted 且通过 `/sync/pull` 回读后，才上传子明细并再次回读。对断网、服务器冲突和未知结果先落盘保留 `needsReview`，**不自动重复上传**；有明确人工按钮核实远端。
6. **保留本地草稿**：任何成功/失败均不会自动删除草稿或覆盖正式经营数据。存储上传意图的账号、账本、域名、payload 与父子 ID 一旦固定便不能替换。旧版本指向其他服务器的上传意图会因目标不匹配而拒绝，不会隐式迁移。
7. **业务写入限制**：营业、凌晨收款、库存利润与结算、客户交易依旧不能从 iOS 写回。Android 的当日结算算法、UI、同步服务端和 APK 工作流均未修改。
8. **回归测试**：单账本身份校验、管理员拒绝、非测试账本拒绝、错误服务域名拒绝、父子 ID 一致、采购金额一致、冲突 ACK、超时恢复、不可变上传意图及单笔验证。

## 立即测试流程

**事先确保服务端确实按用户权限限制账本写入。** 如果还没验证权限，就先登录测试账号确认只能显示测试账本，不要按“确认试写一笔”。

1. 在当前正式服务器里创建一个**全新、独立、无生产交易**的测试账本，例如 `iOS_TEST_采购测试`。不要将正式账本改名！为它建立测试摊位、商品及测试采购人。
2. 创建一个普通的独立测试账号，**只允许访问该测试账本**。此账号登录 `GET /api/v1/books` 只能看到该测试账本；不能是全局管理员，不能授予正式账本权限。
3. 在 iPhone 登录并切换到刚才的测试账本，通过 `更多 → 写入测试实验室` 保存一笔小额采购草稿。此前 V0.2.0 草稿如属于此测试账本可直接复用。
4. 进入 `更多 → 测试账本采购同步`，输入专用测试账号密码、完整测试账本 ID，勾选权限确认。App 再检查测试账号的权限、可见账本数量、ID 与名称。
5. 点击草稿的“核验采购人/商品并准备订单”，查看状态为待上传；然后逐笔明确确认首笔测试上传。
6. Android 用同一服务器登录并打开同一测试账本，核对采购人、商品、金额、数量、单位、采购订单和明细关联以及同步标记。查看正式账本是否完全不变。
7. 如超时、记录冲突或者只成功一部分，**不要重复点上传**，先使用“检查服务器是否已经接收”查远端；出现差异停止验收。

## 下载和测试

Actions → **Build TrollStore IPA (no Apple certificate)** → 最新绿色成功的 V0.2.2 → Artifacts → `TianXianFruit-iOS-v0.2.2-TrollStore`。保留 bundle ID `com.tianxian.fruit.ios`，版本 0.2.2 / build 7。

`ios/scripts/check_readonly.py` 是重要 CI 保护：仅允许 `StagingPurchaseAPI.swift` 持有实际 `/sync/push` 端点，并验证固定正式主机、普通用户单账本、测试前缀、显式确认、独立本机草稿的不可写承诺。

## 仍需服务端确认

- 只有客户端侧的“可见账本恰好一个”**不等于**服务器可写权限的充分证明；尤其管理员隐藏权限、服务端按数字 ID 关联采购明细、跨账本 `purchase_order`/`purchase_item` 远端 ID remap 都需要服务器/Android 端到端核对。
- 当前只开放**首笔单商品采购**；**不开放营业/利润/结算**。没有进行任何生产数据写入或部署服务器。
- 本 GitHub PR 仍保持 Draft，不合并主分支，不触发 Android APK 新发布。
